# 修理事例の記事作成ルール

スタッフの報告（業務・事例報告フォーム）から、HPの修理事例記事とGoogle最新情報の下書きを作るときのルール。
下書きを作る人・AI（Claude Code）は、毎回このルールに従う。最終判断と承認はオーナーが行う。

## 1. 大原則

- **報告に書かれた事実だけを使う。** 報告にない作業・部品・症状・結果・お客様の反応・感想は書かない。確認できていない修理内容・効果（「長持ちします」「再発しません」など）・作業日は、推測で足さない。
- スタッフの報告をそのまま転載しない。必要な情報を選び、自然で温かい文章に整える。
- 料金は載せない。
- 掲載日（`date`）と作業日（`workDate`）を混同しない。作業日が確認できないとき（報告日と同じと仮に置いたときを含む）は、本文で日付や「本日」「当日」などの時期を断定しない。未確認の点は `facts.uncertain` に書いて、オーナーの確認に回す。

## 2. 記事の中心（この順で組み立てる）

| 順 | 内容 | 記事での位置 |
|---|---|---|
| 1 | 地域と端末の機種・世代 | タイトル・説明文・「ご相談」の書き出し |
| 2 | お困りだった症状 | 「ご相談」 |
| 3 | 実際に行った修理・メンテナンス | 「修理内容」 |
| 4 | 修理後の結果 | 「修理後」 |
| 5 | お客様の反応（**報告にある場合のみ**） | 「修理後」 |
| 6 | ご来店への感謝 | 「修理後」の締め |

見出しは、公開済みの記事と同じ「ご相談」「修理内容」「修理後」の3つにする。

## 3. 地域の書き方・地域SEO

- **地域の基本は、フォームで選ばれた地域（`facts.area`）。** タイトル・説明文・本文・Google最新情報・写真のaltに自然に入れる。
- **報告文と選ばれた地域が矛盾しないとき（通常）は、自然で温かい表現を優先する。**
  - よい例：「水戸市からお越しのお客様」「水戸市からご来店いただいたお客様」「水戸市のお客様から、〜とのご相談をいただきました」
  - 避ける例：「水戸市エリアでの修理事例です。」のような機械的な書き出し。「〇〇市エリア」は、下の矛盾があるときだけに使う。
- **水戸市の検索対策を重視する。** 地域が水戸市の事例では、次の組み合わせを、不自然にならない範囲で使う。
  - 「水戸市」＋「iPhone修理」「スマホ修理」
  - 「水戸市」＋機種名（例：iPhone 16 Pro）
  - 「水戸市」＋修理症状・修理内容（例：画面割れ、バッテリー交換）
  - 目安：タイトル1回、説明文1回、本文2〜3回、写真のalt・Google最新情報に自然に。同じ言い回しを繰り返して詰め込まない。
  - 事実と違う地域情報は作らない。選ばれた地域が水戸市でない事例に「水戸市」を入れない。
- **報告文と選ばれた地域が矛盾するとき**（報告文に別の地名がある、来店元がはっきりしないなど）：
  - その矛盾を `facts.uncertain`（承認画面の「確認が必要な点」）に必ず書く。
  - オーナーが確認するまでは、来店元・居住地を事実として断定しない。「〇〇市からお越しの」「〇〇市にお住まいの」は使わず、「〇〇市周辺でiPhone修理をお探しの方へ」のように、エリアとして書く。
- 選ばれた地域以外の市町村名は本文に書かない（自動チェックで止まる）。
- **店舗所在地は茨城町のまま正確に書く。** お客様の地域を店舗所在地として書かない。地域が不明なとき、店舗所在地（茨城町）で埋めない。

## 4. お客様の個人情報

- 年齢・年代・性別は、報告に書かれていても原則として載せない。家族の年齢や家族の詳しい情報など、修理事例に不要な情報も省く（報告にあっても、下書き作りは止めずに必要な情報だけを選ぶ）。
- 「親子でご来店いただきました」のように、修理のエピソードとして自然な情報は、必要に応じて残してよい（年齢・学年・続柄の詳細は書かない）。
- お客様を特定できる情報（名前、勤務先・学校、細かい住所、来店の具体的な日時と組み合わせた特徴など）は載せない。
- 写真は、顔・名前・画面の表示内容・伝票・ラベル・QRコード・管理番号が写っていないものだけを使う（オーナーが承認画面で「公開OK」にしたもの）。

## 5. 文章

- 機種名・症状・修理内容・修理後の結果を中心に、読みやすくまとめる。
- 報告文をそのまま載せず、丁寧で温かい、お店の人が書いたような文章に整える。専門用語は短く言い換える。
- **言い回し・感謝の伝え方・文章の組み立ては、毎回少しずつ変える。** 同じ定型文を使い回さない。直前の事例と同じ書き出し・締めの文にしない（書く前に、直近の修理事例の書き出しと締めを確認する）。
  - 感謝の例（言い回しの方向性。そのまま固定しない）：
    「水戸市からお越しいただき、ありがとうございました。」
    「数あるお店の中からご相談いただき、ありがとうございます。」
    「またスマホのことで気になることがあれば、いつでもお声がけください。」
    「大切なiPhoneを安心してお使いいただけるよう、これからもお手伝いします。」
- 報告にお客様の反応がないときは、「喜んでいただけました」などを書かない。結果（動作の確認など）と感謝だけで締める。
- 1段落は2〜3文。本文全体は300〜500文字程度を目安にする。

## 6. 下書きの項目（`drafts.hp`）

| 項目 | 書き方 |
|---|---|
| `slug` | `掲載日-地域-機種-修理内容`（英小文字・数字・ハイフン。例 `2026-11-18-mito-iphone16pro-screen-repair`） |
| `titleArea` / `titleDevice` / `titleServices` | タイトル `【地域】機種の修理内容｜オシスマ修理事例` の部品。地域・機種は報告と完全に同じにする |
| `description` | 120文字前後。地域・機種・症状・修理内容を自然に入れる |
| `cardSummary` | 一覧のカード用に40〜60文字 |
| `sections` | 「ご相談」「修理内容」「修理後」 |
| `featureMedia` / `cardMedia` | 公開OKの写真から選ぶ |

写真のaltは「地域＋機種＋写っている作業」を自然な日本語で（例「水戸市からお越しのお客様のiPhone 16 Pro、画面交換の作業中の様子」）。写っているものは、オーナーの説明や写真の判定にあることだけを書く。

## 7. Google最新情報（`drafts.gbp`）

- HP記事と同じ事実だけで、短く（300〜500文字程度、上限1500文字）。電話番号・URLは本文に入れない（「詳細」ボタンで記事へリンクする）。
- 地域・機種・症状・修理内容を自然に入れ、最後に感謝を一言。

## 8. 提出前の確認

- [ ] 報告にない作業・症状・反応を書いていない
- [ ] 作業日が未確認なら、日付・時期を断定していない
- [ ] 年齢・年代・性別・料金・個人を特定できる情報がない
- [ ] 地域は選ばれた地域。矛盾がなければ「〇〇市からお越しのお客様」など自然な表現になっている（「〇〇市エリアでの修理事例です」のような機械的な書き出しではない）
- [ ] 報告文と地域が矛盾すれば、`facts.uncertain` に書き、来店元・居住地を断定していない
- [ ] 確認できていない修理内容・効果・作業日を足していない
- [ ] 店舗所在地は茨城町のまま
- [ ] 感謝の言い回しが直前の事例と同じではない
- [ ] `node tools/cases/...` の自動チェック（`validateReport`）でエラーがない
